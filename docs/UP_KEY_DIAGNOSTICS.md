# Windows 上方向键只读检测

此工具用于排查项目部署时遇到的持续上键问题，不参与视频分析。它不修改注册表、驱动或键盘设置，不停止任何程序，不生成或屏蔽按键。

在本机仓库目录运行（只需已安装的 Python 3.12，无需完成模型部署）：

```powershell
py -3.12 tools\diagnose_up_key.py --seconds 20
```

看到 `Recording ONLY Up-arrow events` 后，短按一次实体上方向键并松开，等待 20 秒自动结束。此次测试只用实体上键；屏幕键盘点击属于另一类输入，宜另开一次检测。工具只记录上方向键的事件时间、按下/释放、扫描码与注入标记，不读取其他键、输入文字或剪贴板。

结果写入忽略的 `.local/up-key-<时间>.json`。报告包含：

- `summary`：按下/释放次数，未释放时的重复次数，软件注入次数。
- `events`：仅上方向键的时间序列。
- `inventory`：键盘驱动提供方/版本/INF、键盘类过滤器，以及可能与输入有关的运行程序名称和 PID。不包含完整进程命令行、环境变量或启动参数。

解释边界：

- `injected_events > 0` 表示观测到带软件注入标记的事件，不能由此识别发送进程；屏幕键盘和远程输入也可能使用该标记。
- 多次 `down` 没有 `up`，且手指已经松开，提示释放事件缺失；可能来自设备、驱动或未带注入标记的输入源，不能直接判定物理损坏。
- 正常按住按键时也会重复 `down`，需要与实际按键时间对照。
- 候选进程列表只提供排查线索，不证明某程序有问题。
- 没有事件不能证明问题不存在；需要在捕获期间复现。

把报告交给诊断人员后，按具体证据逐项退出可疑软件进行对照测试；保存工作后再操作。不要批量停止所有程序或随意卸载键盘驱动。当前云端无法替代本机事件检测。
